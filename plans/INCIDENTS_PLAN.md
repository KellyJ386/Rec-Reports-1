# Incident & Accident Reporting Module — Development Plan

## 1. Current state

- **DB schema exists** in `supabase/migrations/0004_incidents.sql`: `incident_reports`, `incident_people`, `incident_attachments`, `incident_escalations`, `incident_followup_actions`, `incident_audit_events`, `incident_amendments`, with facility-scoped RLS on all seven tables gated by `incidents.read` / `incidents.manage` (tightened with `deleted_at is null` in `supabase/migrations/0009_rls_hardening.sql`). Design tables `incident_witness_statements`, `incident_signatures`, `incident_training_triggers`, `incident_compliance_checks` do **not** exist.
- **Hash-chain infrastructure exists**: `supabase/migrations/0013_audit_chain.sql` adds `prev_hash`/`row_hash` to `incident_audit_events` with a DB trigger; `src/lib/audit.mjs` has `computeRowHash`/`verifyChain` helpers — but nothing in the incidents module *writes* audit events yet.
- **Domain lib** `src/lib/incidents.mjs` (tested in `test/incidents.test.mjs`, 5 tests): `shouldEscalateIncident`, `escalationDueAt`, `isEscalationOverdue`, `classifyOshaReview`, `requiredIncidentFollowUps`, driven by settings-registry keys `incidents.escalationSlaHours` and `incidents.severityAutoEscalate`.
- **Routes** `src/lib/http/incidents-routes.mjs` (tested in `test/incidents-routes.test.mjs`, 10 tests): only 4 endpoints — list by facility (`?status=` filter), get by id, create **draft** (never leaves draft; no submit/transition endpoint), and `POST /incidents/:id/escalate` (hardcoded level 1 / `manager` target). Guarded by `incidents.read`/`incidents.manage` via `requireAuthPermission`.
- **Permissions**: only `incidents.read` and `incidents.manage` exist (`src/lib/permissions.mjs`, `supabase/seed.sql`); the design's 9 fine-grained codes (`incidents.review`, `incidents.escalate`, `incidents.legal_hold.manage`, `incidents.export.pdf`, etc.) are not defined.
- **UI**: read-only card list of the 5 newest incidents in `src/public/index.html` (`#incidents-list` panel) rendered by `loadIncidents()` in `src/public/js/app.js`; no capture form, no wizard, no review workspace.
- **Reusable platform pieces**: zero-dependency PDF renderer at `src/lib/admin/pdf.mjs` (used by admin export); notification routing tables (`0016_notifications.sql`) + pure resolver lib `src/lib/admin/notifications.mjs` + `notification_jobs` fan-out table (`0006_communications.sql`) — but **no dispatch worker** and **no Supabase Storage integration anywhere** in server code.
- **RLS SQL test harness exists** (`supabase/tests/*.sql` run by `scripts/run-rls-tests.mjs`, transaction-rollback fixture style per `tenant_isolation.sql`) but contains **no incident-specific test file**.
- **Adjacent modules ready for linking**: `src/lib/http/work-orders-routes.mjs` (facility-scoped create), `src/lib/http/training-routes.mjs` (assignments), both following the identical injected-primitives route pattern.

## 4. Dependencies

- **Work Orders module** (IN-17): needs a reusable create helper extracted from `src/lib/http/work-orders-routes.mjs` (currently create logic is inline in the route). Schema link column (`incident_followup_actions.work_order_id`) lands in IN-11.
- **Training module** (IN-17): `incident_training_triggers` FKs into `training_assignments` (0007); assignment-creation helper must be exported from `src/lib/http/training-routes.mjs` / `src/lib/training.mjs`.
- **Admin settings** (`src/lib/settings-registry.mjs`, `0008_admin_config.sql`): existing keys `incidents.escalationSlaHours`, `incidents.severityAutoEscalate`; new keys needed for OSHA decision tree (IN-14), retention matrix (IN-16/IN-25), quiet-hours bypass (IN-20). Follow the registry's default-shipping pattern and `scripts/gen-settings-check.mjs`.
- **RBAC/permissions** (0012, `supabase/seed.sql`): IN-01 is a prerequisite for nearly everything in M1/M2 — the design's permission matrix cannot be enforced with only `incidents.read`/`incidents.manage`.
- **Storage infrastructure** (IN-07): **does not exist platform-wide** — no Supabase Storage client anywhere in `src/lib`. Building it inside this module makes it the platform primitive; Daily Reports photo attachments (roadmap MVP item B) will reuse it. Requires bucket provisioning + storage RLS policies + env config in `src/lib/env.mjs`.
- **Notification worker**: tables (0006/0016) and pure routing lib exist, but there is no dispatcher. IN-20 only *enqueues* `notification_jobs`; actual delivery depends on the platform notification worker (out of module scope). IN-21's sweep needs a scheduler entry point (cron/Vercel scheduled function — `vercel.json` present).
- **Audit backbone** (0010/0013): incident ledger hashing is handled by DB trigger; module code must insert events with correct canonical fields and may reuse `src/lib/audit.mjs` `verifyChain` for IN-22.
